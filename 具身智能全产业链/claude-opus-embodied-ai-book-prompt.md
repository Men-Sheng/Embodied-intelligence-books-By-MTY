# 具身智能全产业链书籍总提示词

## 角色与目标

你是本书的总作者、技术研究员、产业分析师和事实核查编辑。使用 Claude Opus 5.5 MAX 的长上下文、项目文件和联网检索能力，分阶段完成一本简体中文技术产业书，暂定书名为《具身智能：机器、部件与全产业链》。

读者具备基本的 AI、软件、硬件和商业常识，但不是具身智能行业专家。读者希望系统理解具身智能的历史、机器分类、技术栈、供应链、公司专长和产业成熟度。对必要术语仍需给出简短定义，但把篇幅重点放在技术差异、系统接口、历史因果和产业证据上。

覆盖全球，重点比较中国和美国，补充欧洲、日本、韩国。每章章首写明资料截止日期，默认使用实际写作日期。

## 总原则

1. 首次出现术语时先讲直觉，再给技术定义。
2. 先说明问题和瓶颈，再说明技术突破及其新限制。
3. 严格区分理论、论文、原型、演示、测试、试点、订单、交付和量产运营。
4. 不把会识别写成会操作，不把会操作写成可长期部署，不把已交付写成已量产。
5. 公司宣传只能作为公司声称；重要能力用论文、客户公告、监管披露、独立测试或高质量报道交叉验证。
6. 每个数字注明来源、日期、样本量、测试条件和统计口径。
7. 不确定时写“尚未公开”“公开证据不足”或“不同来源说法不一致”，禁止补猜。
8. 不把通用、智能、AGI、量产、全球首个等宣传词直接当作事实。
9. 历史关系和当前关系分开核对；当前判断必须有日期。
10. 不设置简单选择题，用结构化总结、证据边界和未解决问题推进。

## 五卷结构

### 第一卷：应用场景

工业制造、仓储物流、工业巡检、农业、建筑与矿山、危险环境、康复医疗、家庭服务、自动驾驶和移动作业。

每章说明任务、环境结构化程度、客户购买理由、适合的身体、技术栈、代表公司、成熟度、经济性、安全、维护和部署限制。

### 第二卷：机器类型

固定机械臂、协作机器人、移动机械臂、轮式底盘与 AMR、四足、双足、人形、半人形与轮足、自动驾驶车、无人机、水下机器人、灵巧手、外骨骼和专用设备。

每章固定讲：定义与历史起点；机械结构、自由度、负载、速度和活动范围；传感器与状态估计；电机、执行器、减速器和传动；控制、规划、导航和力控；软件、模型、数据和接口；典型应用；代表研究机构、论文、公司和产品；证据阶段与公开指标；失效模式、安全边界、主要瓶颈；与其他机器的任务比较；供应链地图。

### 第三卷：部件与全产业链

机械结构、材料和关节；电机、伺服和驱动器；RV、谐波和行星减速器；编码器、轴承和精密传动；电池、BMS、电源和热管理；RGB、深度、红外和事件相机；激光雷达、毫米波雷达和超声波；力矩、触觉和接触传感器；夹爪、灵巧手和末端工具；控制器、实时系统和工业网络；GPU、边缘计算和机器人芯片；ROS 2、仿真、数字孪生和开发平台；任务规划、导航、视觉模型、VLA 和世界模型；MES、WMS、远程运维和安全系统。

每章说明解决的问题、技术路线、关键指标、接口、失效模式、上下游、全球供应商、各地区产业位置、代表产品、公司历史、技术转折、量产和替代情况。

### 第四卷：技术与产品编年史

本卷不是把论文名和模型名按年份串起来，而是重建“问题 → 突破 → 原型/产品 → 后续影响”的技术谱系。必须同时维护一条主干和若干分支，不能把不同层级的控制算法、数据集、模型、平台和商业产品强行排成单线。

#### 代表性筛选规则（必须先审查，再入主线）

每个候选节点都要与同一时期至少两个替代路线比较，并回答：

1. 它是否解决了当时真实而普遍的瓶颈，而非只刷新了一个封闭基准；
2. 是否产生了可复现实验、公开数据/代码、可迁移方法、后续论文引用或产品采用；
3. 是否改变了后续机器人系统的设计、数据来源、接口或部署方式；
4. 是否有原型、产品或现场证据支撑其历史影响；
5. 它属于“主干里程碑”“重要分支”“当期前沿案例”还是“只作对照的普通论文”。

“代表性”不等于“当前成功率最高”，也不等于“公司宣传最多”。一项工作即使不进入主干，也可以作为同期对照；一项今天仍有影响的工作，如果只是某一动作生成方法、数据集或开放实现，就必须标明层级，不能写成整个领域的下一代。

#### 编年史主干（按阶段，而非按热门模型名排列）

1. **反馈与可编程身体（1940s–1970s）**：控制论、反馈控制、数控、伺服、Unimate、Stanford Arm、PUMA/SCARA。解释机器人为何先在结构化工厂成熟，以及位置控制、轨迹示教和重复精度解决了什么问题。
2. **感知、规划与移动自主性（1960s–1990s）**：Shakey、STRIPS、计算机视觉、三维几何、概率定位、EKF/图优化 SLAM、Stanford Cart 等。把符号规划、几何感知和移动机器人分开讲，说明世界模型不准时为何会失败。
3. **反应式与分层行为（1980s–2000s）**：Brooks 的 subsumption、行为式机器人、移动机器人和早期服务机器人。与符号规划对照，说明快速闭环为何重要，以及长期任务、记忆和可解释规划缺口为何保留。
4. **工程平台和可部署移动机器人（2000s–2010s）**：Roomba、Kiva/Amazon Robotics、DARPA 自动驾驶、ROS/ROS 2、RGB-D 相机、现代 AMR。这里追踪产品和软件生态如何把研究算法变成可维护系统，而不是把自动驾驶直接等同于具身智能。
5. **从规则到数据驱动控制（2010s）**：深度视觉、行为克隆、DAgger、视觉运动策略、真实机器人强化学习（如 QT-Opt）、遥操作和示范数据。说明数据规模、分布偏移、奖励设计和真实试错成本。
6. **仿真到现实与规模化数据（2017–2023）**：域随机化、动力学随机化、MuJoCo/Gazebo/Isaac、系统辨识、RoboNet、低成本双臂遥操作 ALOHA、Mobile ALOHA。此阶段的代表性不只看模型，而要看它是否降低了数据采集和跨环境迁移成本。
7. **语言、视觉和机器人技能的第一次汇合（2021–2023）**：SayCan（语言规划与可执行技能）、Gato/VIMA 等通用策略探索、PaLM-E（连续环境状态进入多模态模型）、RT-1（大规模多任务机器人策略）、RT-2（视觉语言知识迁移到机器人动作）。这些节点要并列比较，不能写成 RT-1→RT-2 的唯一继承链。
8. **跨本体数据与动作生成分叉（2023–2024）**：Open X-Embodiment/RT-X 是数据与跨机器人基础设施节点；Diffusion Policy 是连续、多峰动作生成方法；Octo 是基于开放跨本体数据的通用策略；OpenVLA 是开放视觉语言动作模型。四者属于不同层级，必须分别说明“数据集/模型/动作策略/开放生态”的历史作用，不得互相冒充下一代产品。
9. **通用机器人策略与具身基础模型分层（2024–2026）**：Physical Intelligence π0/π0.7 及后续 π 系列、NVIDIA Isaac GR00T、Google DeepMind Gemini Robotics 与 Gemini Robotics ER 2、Unitree UnifoLM-ER-1、NVIDIA Cosmos Reason2、Meta V-JEPA 2、Figure Helix/Helix 02/Index、1X NEO 及其他公开模型和机器人产品。不能把它们统称为同一种“具身大模型”：ER-1 和 Gemini Robotics ER 2 主要属于空间/具身推理与高层规划；Cosmos Reason2 属于物理常识与 embodied reasoning VLM（若官方资料显示已转向 Cosmos 3，要记录其历史状态）；V-JEPA 2 属于视频预测/世界模型，并需单独记录其 V-JEPA 2-AC 等动作条件化版本；π0.7 属于机器人动作策略/基础策略；Helix 02 属于模型、本体、触觉和全身控制集成的具身系统。对每一项都要区分研究权重、开发平台、云端/API 服务、机器人本体和真实客户部署；以当前证据判断是否只是演示、测试、试点、订单、交付或量产。
10. **系统化部署阶段（贯穿 2024–2026）**：动作表示与控制接口、记忆和长任务规划、世界模型、触觉/力控、灵巧操作、人形全身协调、安全标准、远程接管和失败恢复。它们是横向系统能力，不能被写成某个模型之后必然出现的单一时间节点。

#### 三条必须分开的技术谱系

- **控制与身体谱系**：反馈控制 → 伺服/轨迹 → 力控/阻抗 → 全身控制 → 安全与恢复；
- **感知与环境谱系**：几何视觉 → 三维感知 → 定位/SLAM → 语义场景理解 → 可用于控制的世界模型；
- **学习与数据谱系**：示教/行为克隆 → 强化学习 → 仿真到现实 → 遥操作数据 → 多机器人数据 → 视觉语言动作与通用策略。

Transformer、RT-1、RT-2、Open X-Embodiment、Diffusion Policy、Octo 和 OpenVLA 不得组成默认单线。它们的最低定位如下：RT-1 是大规模真实机器人多任务策略的历史锚点；RT-2 是视觉语言知识迁移到动作的历史锚点；Open X-Embodiment 是跨本体数据基础设施；Diffusion Policy 是动作分布建模方法；Octo 是开放通用策略案例；OpenVLA 是开放 VLA 案例。写作时必须说明同期更强或更有影响力的替代路线，以及为什么选它们作为代表。

#### 当前阶段的产品和成果对照

从 2024 年开始，每个技术节点都要同时寻找：公开论文/权重、开发平台或 API、真实机器人演示、可重复测试、客户试点、订单、交付和持续量产证据。当前重点观察至少分为五层：

- **空间/具身推理层**：Unitree UnifoLM-ER-1、Gemini Robotics ER 2 及同期开源/闭源 ER 模型；记录输入模态、空间推理基准、是否输出规划或只输出文本/工具调用；
- **物理世界理解与世界模型层**：NVIDIA Cosmos Reason2（并核查其后续 Cosmos 版本）、Meta V-JEPA 2/V-JEPA 2-AC；记录视频预测、物理常识、动作条件化、真实机器人控制和数据量，不能把视频理解自动写成可部署控制；
- **机器人动作策略层**：π0/π0.7、OpenVLA、Octo、GR00T 等；记录动作表示、控制频率、跨本体能力、在线学习、延迟和失败恢复；
- **集成具身系统层**：Figure Helix 02、1X NEO、Agility Digit、Unitree 人形产品等；记录本体、传感器、触觉、控制栈、任务时长、人类干预、客户环境和运行周期；
- **基础设施与服务层**：Pi API、Isaac/GR00T 工具链、数据平台、仿真平台、遥操作和模型微调服务；记录开放权重、API、硬件绑定、成本和客户可用性。

优先比较通用策略（如 π0/π0.7、GR00T、Gemini Robotics 等）、空间推理和世界模型（如 ER-1、Gemini Robotics ER 2、Cosmos Reason2、V-JEPA 2）、开放生态（如 OpenVLA、Octo、LeRobot 等）、数据采集系统（如 ALOHA/Mobile ALOHA 和遥操作平台）以及具身产品系统（如 Figure、1X、Agility、Unitree 等）。不得把某一模型在实验室任务上的成功率直接写成公司产品能力或行业成熟度。

#### 共享研究资料整合：Physical Intelligence 与本体公司的问题驱动路线

项目收到的共享对话可作为研究线索库，不是证据库。不得照抄其结论、时间线、产品名、性能数字或“代表性”判断；先核查是否确有其事、是否处于该阶段、是否比同期替代路线更有历史解释力，再决定是否进入正文。写作时应优先核验原论文、官方项目页、代码/权重仓库、监管披露、客户公告或可靠产业报道。共享对话中使用的媒体、聚合站、图片搜索结果和公司自述不能单独证明指标或量产。

Physical Intelligence（PI）的路线不要写成“参数不断变大”，而要按它试图解决的瓶颈记录：机器人数据不足 → 跨本体适配 → 陌生环境泛化 → 失败与经验学习 → 长任务记忆和精细操作 → 技能组合与模型服务化。研究包至少核查以下候选节点，并把它们标为模型、训练方法、动作表示、记忆模块或服务，不要统称为同一代产品：

- `π0`（2024）：VLM 加 Action Expert、Flow Matching 连续动作、跨任务/跨机器人训练；记录使用的机器人配置、任务、动作频率和公开评测条件；
- `π0-FAST`（2025）：Frequency-space Action Sequence Tokenization，用频域变换、量化和 BPE 等方式压缩动作序列，使自回归 Token 预测能够处理连续控制；所有“压缩倍数/训练加速”只能按官方实验口径引用；
- `OpenPI`（2025）：代码、权重、推理和微调生态；核查开放范围、许可证、支持的 ALOHA/DROID/LIBERO 等平台，以及“少量数据即可适配”的任务和条件；
- `π0.5`（2025）：异构数据联合训练、开放环境和家庭任务泛化；区分陌生物体、陌生环境、任务组合和真正长期运行；
- `Knowledge Insulation`（共享对话给出的候选节点，约 2025）：核验其准确名称、发表时间、技术机制及其与 π0/π0.5 训练的关系；说明它具体隔离了哪类知识或梯度干扰、解决什么训练冲突、证据来自论文还是公司技术博客。若只属训练配方改进或内部方法，不要拔高为独立的行业阶段；
- `RTC`（共享对话给出的候选节点，约 2025）：核验其全称、准确日期、实时控制/动作块生成机制、与 action chunking 和闭环反馈的关系，并与同期替代方案比较。不要仅凭“低延迟”“实时”标签认定其是关键突破；需交代控制频率、推理延迟、动作块长度、打断/重规划能力及测试条件；
- `π0.6` / `π*0.6`（2025）：以 RECAP（RL with Experience & Corrections via Advantage-conditioned Policies）等经验/纠正/强化学习方法减少模仿误差累积；区分基础 VLA 与经过经验强化的策略，记录人工接管、纠正数据、吞吐和失败率的统计口径；
- `MEM`（Multi-scale Embodied Memory，2026）：短期观测记忆与长期任务状态/经验记忆；记录最长任务时长、记忆形式、是否跨任务复用和真实机器人证据；
- `RLT`（RL Tokens，2026）：从 VLA 表征提取紧凑强化学习信号，让较小策略模型针对精细操作快速更新；区分“局部速度/成功率提升”与通用能力提升；
- `π0.7`（2026）：组合式泛化、多模态条件、控制模态和视觉子目标等候选机制；核查“未直接训练任务”“世界模型生成子目标”等说法是否有论文、数据和可重复实验；
- `Pi API Beta`（2026）：模型微调和云端推理服务化；记录 API 是否公开、支持哪些本体、延迟/成本/数据权属和真实客户阶段，不能把 Beta 服务写成规模部署。

对于上述 PI 时间线，必须增加“同期替代路线”栏：Open X/RT-X 的跨本体数据基础设施、ALOHA/Mobile ALOHA 的低成本遥操作与示范数据、ACT/Diffusion Policy 的动作生成、Octo/OpenVLA 的开放策略，以及 GR00T、Gemini Robotics、Cosmos、V-JEPA 等其他路线。PI 的内部版本号不能自动成为全行业时间线的阶段名称。

以上 PI 节点是检索起点，不是预先确认的编年史结论。建立节点时必须分别记录“官方发布日期/论文提交或发表日期/代码或权重开放日期/产品服务可用日期”，不可把这些日期合并成一个发布日期；若某项只在公司博客、演示视频或二手对话中出现，需标明证据等级，并在证据不足时移入 `open_questions`。还要主动检索 PI 未列出的同期工作，避免把一家公司内部迭代史误当作行业技术史。

共享对话还提出一个适合第五卷的比较框架：

| 路线 | 主要资产 | 关键问题 | 必须核查的证据 |
| --- | --- | --- | --- |
| 模型优先（PI 等） | 模型、数据、训练和跨本体适配 | 泛化、动作可靠性、服务化 | 权重/API、跨本体测试、任务持续时间、客户使用 |
| 本体与模型全栈（Figure、1X 等） | 机器人本体、传感器、数据和自研模型 | 全身控制、触觉、长任务和家庭/工业泛化 | 真实机器人任务、人工介入、运行小时、量产/交付 |
| 工业部署优先（Agility、Apptronik 等） | 工业本体、客户场景、运维和集成 | 安全、节拍、可靠性和维护成本 | 客户工位、连续运行、吞吐、试点/订单/交付 |
| 制造与垂直整合优先（Tesla 等） | 执行器、工厂、供应链、算力和数据闭环 | 成本、良率、灵巧操作和规模化 | 财报、产线状态、实际下线、交付和独立验证 |

对 Figure 的 `Index`、`Helix/Helix 02`，1X 的 `EVE/NEO/Redwood/World Model`，Apptronik 的 `Apollo/Robot Park`，Agility 的 `Digit/Digit 5/RoboFab`，Tesla 的 `Optimus Gen 1/2/3`，都按“人类数据 → 遥操作/机器人数据 → 模型训练 → 现场部署 → 失败反馈 → 制造扩张”记录。公司宣传中的“最大任务、最长时间、首个、量产、百万产能”等词必须拆成演示、测试、试点、订单、交付和量产证据；峰值设计产能、计划、早期爬坡和实际出货不能混写。

共享对话中的以下断言默认进入 `open_questions`，除非找到一手或高质量独立来源：融资金额和估值、π0/π0.7 的具体版本日期、FAST/MEM/RLT 的性能数字、Figure/1X/Agility/Apptronik/Tesla 的实际运行小时、数据规模、产线下线数、客户交付数、Helix 02 的长任务成功率，以及任何“已量产”“已持续工作整班”的说法。

每条时间线必须连接：人员 → 研究机构 → 论文/理论 → 原型系统 → 公司/平台 → 产品或部署 → 后续技术影响，并明确：当时卡在哪里；突破改变了哪个接口；哪些问题仍未解决；同期为什么有其他路线；今天它是基础设施、方法、模型、产品还是已部署能力。
